# 05. 로드맵 · 법규 · 리스크

## 1. 단계별 로드맵

| 단계 | 기간(1~2인 기준) | 산출물 | 완료 기준 |
|---|---|---|---|
| **P0-0 준비** | 1~2주 | 모노레포(pnpm workspace), CI(lint·typecheck·OpenAPI lint·마이그레이션 테스트), **디자인 시스템([06](06-design-system.md)): 토큰·핀·패널·시트·타임라인 컴포넌트**, **카카오 약관 서면 확인(G0)**, 위치기반서비스사업 신고 준비 | `pnpm dev`로 서버·웹·DB가 로컬에서 한 번에 뜬다 |
| **P0-1 서버 코어** | 2~3주 | Auth(이메일·Google·Kakao), Places/Notes/Tags/Categories CRUD, 이벤트 기록, `/map/config`, `/geo/*` 프록시 | OpenAPI 계약 테스트 통과, bbox 조회 p95 < 200ms (장소 1만 개) |
| **P0-2 웹 MVP** | 3~4주 | 지도 홈(MapLibre 회색조 기본지도 + Kakao 어댑터), 데스크톱 플로팅 패널 / 모바일 3단 바텀시트, 장소 상세·타임라인(메모 리비전), 아이콘·색 선택기, 카테고리·태그 필터, 카테고리 관리, 라이트/다크, 링크 공유 페이지(SSR) | Playwright E2E 통과 + 사내 베타 10명이 일주일 사용 |
| **P0-3 공유·출시** | 1~2주 | 사용자 간 공유, 공유받은 레이어, 내보내기(GeoJSON/CSV), 회원 탈퇴 | 공개 베타 |
| **P1 모바일** | 6~8주 | Expo 앱(iOS/Android), 지도 네이티브 모듈(**G1 결정**), 오프라인 동기화, Sign in with Apple, 딥링크, 사진 첨부, 친구 | 스토어 심사 통과 |
| **P2 확장** | 이후 | 커스텀 아이콘, 스마트 필터, 공개 큐레이션, 해외 구글 도입(G2) | — |

## 2. 법규 체크리스트 (출시 전 법무 검토 필수)

| 항목 | 내용 | 설계 반영 |
|---|---|---|
| **위치정보법 — 위치기반서비스사업 신고** | 개인위치정보(특정 개인의 위치)를 이용해 서비스하면 방송통신위원회에 위치기반서비스사업을 신고해야 한다. "현재 위치로 저장"과 "내 위치 표시"가 여기에 해당할 가능성이 크다 | 출시 전에 신고. 가입할 때 **위치기반서비스 이용약관 동의**를 따로 받는다 (`agreements.location`) |
| 위치정보 이용·제공 사실 확인자료 | 수집·이용·제공 사실을 자동으로 기록하고 법정 기간 동안 보존해야 한다 | `location_access_logs` 테이블. 보존 기간은 법무가 확정 |
| 개인위치정보의 제3자 제공 | 공유 기능이 "개인위치정보 제공"에 해당하는지 검토가 필요하다. 해당하면 제공받는 자를 고지하고 동의를 받아야 한다 | 공유할 때 받는 사람을 명시하고 확인 단계를 둔다. `location_access_logs(action='provide', recipient)` |
| 14세 미만 | 개인위치정보는 법정대리인 동의가 필요하다 | MVP는 **만 14세 이상만** 가입 (`agreements.age_14_or_over`) |
| 개인정보보호법 | 수집 항목·목적·보유기간 고지, 파기, 열람·정정·삭제권 | 탈퇴 → 7일 유예 → 하드 삭제, `/export`로 열람권 보장 |
| 데이터 보관 위치 | 국외 이전 고지 의무를 최소화한다 | AWS 서울 / NCP 국내 리전 |
| App Store / Play | 앱 안에서 계정 삭제, Sign in with Apple, 위치 권한 사용 목적 문구, 데이터 안전 섹션 | `DELETE /me`, Apple OIDC, `NSLocationWhenInUseUsageDescription` |
| 지도사 약관 | 저작권 표기, 응답 저장 금지, 타사 지도 혼용 제한 | [02 문서 §4 저장 정책](02-map-provider-research.md#4-데이터-저장-정책-공급자-약관-준수-설계) |
| OSM ODbL | "© OpenStreetMap contributors" 표기 | MapLibre 어댑터에 표기 고정 |

## 3. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 지도사 요금·쿼터 정책 변경 (2025 네이버, 2026 카카오 사례) | 비용 급증 또는 서비스 중단 | 어댑터와 `/map/config`로 바로 전환. MapLibre 폴백. 쿼터 사용률 80%에서 알림 |
| 카카오가 검색 결과로 미리 채우기·좌표 저장을 불허 | 검색해서 저장하는 흐름이 바뀜 | "검색은 지도 이동만, 저장은 사용자가 핀을 확정" UX로 전환 (G0) |
| RN용 카카오 지도 래퍼 부재 | 모바일 일정 지연 | Expo 네이티브 모듈을 직접 개발하거나 네이버로 전환 (G1) |
| 구글의 국내 본격 진입 | 국내 지도 시장 판도 변화 | 데이터를 소유하고 있으므로 해외부터 구글 어댑터를 추가 (G2/G3) |
| 공유로 인한 위치 노출 사고 | 신뢰 손상, 법적 문제 | 기본값은 비공개, 링크 만료와 회수, 비공개 메모 제외, 공유 확인 단계 |
| 동기화 충돌로 데이터 유실 | 사용자 불만 | 필드 단위 LWW + 메모 리비전 보존 + 이벤트 로그로 복구 가능 |

## 4. 바로 다음 할 일 (제안)

1. 모노레포 초기화: `apps/server`(Fastify), `apps/web`(Next.js), `packages/api-client`(openapi.yaml로 생성)
2. `db/schema.sql`을 첫 마이그레이션으로 등록하고, docker-compose(PostGIS) 구성
3. 카카오 디벨로퍼스 앱 생성(회사 대표 계정의 첫 앱) + 약관 문의 (G0)
4. Auth와 Places API 구현 → 웹 지도 홈 → 장소 상세 순서로 수직 슬라이스 완성
